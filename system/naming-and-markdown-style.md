# Naming And Markdown Style

## File Naming

- Use lowercase slugs.
- Use hyphens, not underscores.
- Filename must match `slug`.
- Keep article files in the most specific content folder:
  - `content/pillars/`
  - `content/use-cases/`
  - `content/comparisons/`
  - `content/troubleshooting/`
  - `content/commercial/`

Example:

```text
content/use-cases/url-indexing-for-seo-agencies.md
```

## Slug Rules

- Include the primary keyword when possible.
- Keep slugs readable and durable.
- Do not include dates or years unless the article is explicitly a dated report.
- Do not include claims that may change, such as exact site counts or exact indexing times.

## Markdown Rules

- The frontmatter is the source of truth.
- Do not add an H1 in article bodies when the publishing system uses `title` as the H1.
- Use `##` for major sections.
- Keep sections practical and scannable.
- Use root-relative markdown links in body copy, such as `[free URL indexer guide](/free-url-indexer)`.
- Use bare slugs in `meta.internal_links`.
- Add a FAQ section to every article brief.

## Metadata Rules

Every content file must include:

- `title`
- `slug`
- `description`
- `keywords.primary`
- `keywords.secondary`
- `intent`
- `search_intent`
- `icp`
- `funnel_stage`
- `type`
- `business_goal`
- `meta.cta`
- `meta.internal_links`
- `seo.meta_title`
- `seo.meta_description`
- `editorial_review`

## Style Rules

- Lead with the practical answer.
- Tie advice to one ICP.
- Be honest about search engine uncertainty.
- Use FreeIndexer naturally as a workflow tool.
- Avoid generic SEO filler.
- Avoid unvalidated claims.
- Do not publish internal planning labels such as `Search Promise`, `CTA`, `Draft Notes`, or `Internal Notes`.
